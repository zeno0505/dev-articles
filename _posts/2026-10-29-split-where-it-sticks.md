오늘 하루를 돌아봤는데요. 한 덩어리로 묶여 있던 걸 어디서 나눌지 정하니 기다리거나 지치는 일이 줄어든 이야기로 정리가 되었습니다.

## 배포 묶음은 급한 순서로 다시 자른다

한 번에 나가기로 했던 추가 개발 묶음 안에 빨리 나가야 하는 부분과 조금 늦어도 되는 부분이 섞여 있었습니다. 묶음째로 두면 늦어도 되는 쪽 일정에 급한 쪽까지 끌려갈 가능성이 크다고 봤습니다.

그래서 급한 순서로 묶음을 다시 잘랐습니다. 급한 쪽은 서버의 API 계약이 나오기 전이었는데, 기다리지 않고 응답 형태를 예측해서 먼저 만들었습니다. 예측한 응답은 모킹으로 넣고, 테스트 서버에서 작성 화면과 필수값 안내, 미리보기, 관리자 화면까지 실제로 띄워서 검증해 두었습니다. 저장이나 발행 요청은 보내지 않았습니다.

이렇게 해 두면 계약이 나왔을 때 남는 건 예측한 응답을 실제 계약에 맞추는 작업 하나뿐입니다. 계약을 기다리며 손을 놓는 것보다 예측으로 화면까지 끝내 두고 맞추는 작업만 남기는 게 훨씬 덜 밀린다고 생각합니다.

![하나로 묶여 있던 배포를 급한 쪽과 나중 쪽으로 다시 자르고, 급한 쪽은 API 계약이 나오기 전에 응답을 예측해 모킹한 뒤 화면까지 검증해 두어서, 계약이 나오면 예측한 응답을 실제 계약에 맞추는 작업 하나만 남는다는 흐름 그림](/dev-articles/assets/2026-10-29-split-where-it-sticks-01.png)

## AI가 만든 화면은 분위기와 세부를 나눠서 고친다

AI가 만들어 준 페이지를 직접 써 보며 다듬었는데, 섹션 하나하나가 마음에 안 들 때마다 채팅으로 어느 섹션의 무엇을 어떻게 바꿔 달라고 일일이 설명하는 게 가장 불편했습니다. 고칠 자리를 말로 짚는 것부터가 일이라 몇 번 하다 보니 금방 지쳤습니다.

그래서 고치는 입력은 둘로 나눠야 한다고 봤습니다. 전반적인 분위기는 상단에서 디자인이나 강조색처럼 한 번에 바꾸고, 세부적인 걸 고치고 싶을 때는 미리보기에서 그 자리를 직접 가리켜 요청하는 방식입니다. 디자인 도구에서 주석을 달듯이 미리보기 위에서만 마우스 포인터가 바뀌고 클릭한 자리에 입력창이 뜨면, 「이 섹션에서 이 이미지를 쓰고, 이 문구는 빼 줘」 같은 요청을 그 자리에서 바로 남길 수 있습니다.

여기서 중요했던 건 이렇게 남긴 요청을 그때그때 보내지 않는 것입니다. 섹션마다 주석을 달듯이 수정 요청을 남기면, 이를 묶어서 한 번의 LLM 호출로 잇습니다. 주석을 달 때마다 LLM을 호출하면 그만큼 비용이 들고, 사용자가 기다리는 시간도 매번 늘어나서 UX 측면에서도 좋지 않습니다.

다듬는 단계에서는 AI가 더 잘 만들어 주는 것만큼, 사람이 고칠 자리를 쉽게 짚고 그 요청을 한 번에 넘길 수 있게 해 주는 게 관건이라고 봅니다.

![전반적인 분위기는 상단에서 디자인과 강조색으로 한 번에 바꾸고, 세부를 고칠 때는 두 방식을 비교한 그림. 왼쪽은 주석을 남길 때마다 AI를 호출하고 기다려서 호출마다 비용과 대기 시간이 늘어나는 방식이고, 오른쪽은 미리보기 여러 자리에 남긴 주석을 묶어서 AI를 한 번만 호출하는 방식이다](/dev-articles/assets/2026-10-29-split-where-it-sticks-02.png)

## 원문은 깎지 않고, 걸러 내는 단계를 따로 둔다

여러 팀이 같이 쓰는 내부 문서를 AI가 사용자에게 안내할 때 쓰는 지식으로 옮기는 작업이 있었습니다. 수정본을 보니 사용자에게 보이면 안 되는 내용을 원문에서 직접 지워 가는 방식이었습니다.

다만 원문은 개발과 기획에서 기준으로 계속 써야 하는 문서라, 안내용에 맞춰 깎으면 원래 쓰던 팀이 보던 내용이 사라집니다. 그래서 원문은 그대로 두고, 사용자 안내용으로 걸러 내는 단계를 따로 두자고 했습니다.

실제로 걸러 낼 기준을 적어 보니 관리자만 쓰는 기능이 모인 폴더, 내부용 장, 내부 주소가 적힌 줄처럼 대부분 패턴으로 잡혔습니다. 기준이 패턴으로 잡히면 원문이 바뀌어도 같은 기준으로 다시 거르면 되니, 원문과 거르는 단계를 나눠 두는 게 맞다고 생각합니다.

![여러 팀이 같이 쓰는 원문은 개발과 기획 기준으로 그대로 두고, 관리자 전용 기능 폴더, 내부용 장, 내부 주소가 적힌 줄처럼 패턴으로 잡히는 기준으로 걸러 내는 단계를 따로 거쳐 AI 안내용 지식을 만들며, 원문을 직접 깎으면 원래 쓰던 팀이 보던 내용이 사라진다는 흐름 그림](/dev-articles/assets/2026-10-29-split-where-it-sticks-03.png)

셋 다 한 덩어리를 어디서 나눌지 정하는 이야기였고, 앞으로도 막히거나 지칠 때는 나눌 자리부터 찾아보려고 합니다.

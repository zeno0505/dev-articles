대비를 맞추는 일과, 그 사람이 고른 색을 지키는 일은 같은 칸이 아닙니다. 소개 화면에서 사용자가 고른 원색을 구역 바탕으로 쓰다 보니, 그 위에 올린 흰 글자가 대비 기준을 못 넘었습니다. 흰 글자를 유지하려고 바탕 명도를 계산으로 내리면 될 거라고 봤습니다. 시안에서 밝은 산호색이 훨씬 어둡고 탁한 붉은색으로 바뀌어, 그 방법과 밝은 색을 막는 방법은 쓰지 않기로 했습니다.

이 글은 사용자가 고른 색을 구역 바탕으로 쓸 때, 대비를 맞추려고 그 색을 바꿀지를 가려야 하는 분께 도움이 됩니다.

## 한눈에 보는 결론

- 제약: 고른 색은 그 사람의 인상이라 그대로 두고, 일반 텍스트 4.5:1, 큰 텍스트 3:1을 통과해야 합니다.
- 결정: 큰 제목은 색 위에 짙은 글자, 본문은 흰 카드, 강조는 밑칠로 맞춥니다. 바탕을 어둡게 하거나 밝은 색을 막는 방법은 쓰지 않기로 했습니다.
- 확인: #f08080과 흰 글자는 2.59:1로 두 기준을 못 넘겼고, 바탕을 #b15e5e로 낮추면 4.53:1이 되지만 명도는 72.2에서 53.1로, 채도는 78.9에서 34.7로 바뀌었습니다. 같은 산호색 위 검은 글자는 8.10:1이었습니다. 휴대 전화 너비 미리보기에서 고른 색이 그대로이고 글자를 읽을 수 있는지를 확인했습니다.

## 제약에 맞춰 고른 방법

바탕 명도를 계산으로 내리는 방법은 가장 단순했습니다. 흰 글자를 유지할 수 있고, 숫자만 보면 기준을 통과합니다. 다만 사용자가 고른 밝은 산호색이 훨씬 어둡고 탁한 붉은색으로 바뀝니다. 고른 색이 그 사람의 인상이라면, 대비를 위해 그 색을 바꾸는 일은 다른 색을 보여주는 일과 같습니다. 그래서 이 방법은 쓰지 않기로 했습니다.

너무 밝은 색을 고르지 못하게 막는 방법도 보았습니다. 대비는 쉽게 맞출 수 있지만, 밝은 색 자체를 쓰지 못하게 됩니다. 고른 색을 다시 바꾸라고 묻는 방법도, 이미 정한 인상을 흔들어 택하지 않았습니다.

## 기본 구조

WCAG 2.1은 sRGB에서 상대 휘도를 L = 0.2126R + 0.7152G + 0.0722B로 정의합니다. 각 채널은 8비트 값을 255로 나눈 뒤, 0.04045 이하면 12.92로 나누고, 그보다 크면 ((값 + 0.055) / 1.055)^2.4를 씁니다. 대비는 더 밝은 휘도 L1과 더 어두운 휘도 L2로 (L1 + 0.05) / (L2 + 0.05)입니다.

![고른 색은 두고, 글자와 배치로 대비를 맞춘다](/dev-articles/assets/2026-10-27-fixed-or-changeable-01.png)

실제 고친 모양은, 고른 색의 16진 값은 바꾸지 않고, 그 위에 올릴 글자 색과 본문 배치만 고르는 함수입니다.

```js
export function contrastRatio(a, b) {
  const first = relativeLuminance(a)
  const second = relativeLuminance(b)
  const lighter = Math.max(first, second)
  const darker = Math.min(first, second)
  return (lighter + 0.05) / (darker + 0.05)
}

export function planOnBrandColor(brand, { white, black }) {
  const withWhite = contrastRatio(brand, white)
  const withBlack = contrastRatio(brand, black)
  if (withWhite >= 4.5) {
    return { brand, title: white, bodyOnCard: true }
  }
  return { brand, title: withBlack >= 4.5 ? black : white, bodyOnCard: true, highlight: 'underline' }
}

function relativeLuminance([red, green, blue]) {
  const channel = (value) => {
    const srgb = value / 255
    return srgb <= 0.04045 ? srgb / 12.92 : ((srgb + 0.055) / 1.055) ** 2.4
  }
  return 0.2126 * channel(red) + 0.7152 * channel(green) + 0.0722 * channel(blue)
}
```

#f08080의 상대 휘도는 0.3552였습니다. 흰 글자와의 대비는 2.59:1로 두 기준을 모두 못 통과했습니다. 흰 글자 기준으로 4.5:1을 만들려면 바탕의 상대 휘도가 0.1833 이하여야 해서, 같은 색을 검게 가깝게 줄여 #b15e5e를 얻었습니다. 시안에서 본 탁한 붉은색이, 이 계산이 가리키는 변화와 같았습니다. 같은 #f08080 위에 검은 글자를 올리면 대비는 8.10:1이었습니다.

## 시안을 고르기까지

### 바탕을 낮추면 흰 글자를 유지할 수 있다고 봤다

흰 글자를 지키려고 바탕 명도를 계산으로 내리면 될 거라고 봤습니다. 시안에서 밝은 산호색이 훨씬 어둡고 탁한 붉은색으로 바뀌었습니다.

### 두 배치를 나란히 본 뒤 카드 쪽을 골랐다

큰 제목은 색 위에 짙은 글자로 두고 본문은 흰 카드에 두는 안과, 다른 배치 안을 나란히 본 뒤 카드 쪽을 골랐습니다. 강조는 색을 바꾸는 대신 밑칠처럼 따로 표시하는 쪽으로 나누었습니다.

### 미리보기에서 색이 그대로인지를 봤다

휴대 전화 너비로 미리보기를 열어, 고른 색이 그대로이고 글자를 읽을 수 있는지를 확인했습니다.

## 한계

고른 색을 지키면, 밝은 바탕 위에 흰 글자를 쓰는 조합은 포기하게 됩니다. 대비만 올라가고 색의 16진 값이나 명도, 채도가 바뀌었다면, 이 글의 기준으로는 통과가 아닙니다.

## 확인 방법

공식과 같은 계산으로 상대 휘도와 대비를 다시 풉니다. 일반 텍스트 4.5:1과 큰 텍스트 3:1을 각각 통과하는지를 적습니다. 그리고 고른 색의 16진 값, 명도, 채도가 그대로인지를 같이 봅니다. 글자 색만 바꾼 조합에서는 바탕 색이 기준 값과 같아야 합니다.

저는 흰 글자를 지키려고 바탕을 낮추면 숫자가 맞을 거라고 봤습니다. 계산을 풀어 보니 그 방법은 숫자를 맞추는 대신 색을 바꿨고, 글자를 짙게 하고 본문을 카드에 두는 방법은 고른 색을 유지한 채 기준을 넘었습니다.

## 정리

- 대비를 맞추려고 고른 색의 명도를 낮추지 않습니다.
- 제목은 짙은 글자, 본문은 흰 카드, 강조는 밑칠로 나눕니다.
- 통과 여부는 대비와 색이 그대로인지를 같이 봅니다.

대비는 고른 색을 바꾸지 않고, 글자와 배치처럼 바꿔도 되는 쪽에서 맞추려고 합니다.

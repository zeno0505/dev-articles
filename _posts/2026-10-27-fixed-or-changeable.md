사용자가 고른 밝은 산호색 #f08080 위에 흰 글자를 올리면, WCAG 상대 휘도로 계산한 대비는 2.59:1이었습니다. 일반 텍스트 기준 4.5:1에 못 미쳤고, 큰 글자 기준 3:1에도 못 미쳤습니다. 흰 글자를 유지한 채 바탕만 어둡게 하면 대비는 4.53:1까지 올라갔지만, 색은 #b15e5e가 되어 명도는 72.2에서 53.1로, 채도는 78.9에서 34.7로 함께 달라졌습니다. 그래서 고른 색은 두고, 글자를 짙게 바꾸는 쪽을 택했습니다.

## 상대 휘도를 그대로 계산해 세 조합을 비교했습니다

WCAG 2.1은 sRGB에서 상대 휘도를 L = 0.2126R + 0.7152G + 0.0722B로 정의합니다. 각 채널은 8비트 값을 255로 나눈 뒤, 0.04045 이하면 12.92로 나누고, 그보다 크면 ((값 + 0.055) / 1.055)^2.4를 씁니다. 대비는 더 밝은 휘도 L1과 더 어두운 휘도 L2로 (L1 + 0.05) / (L2 + 0.05)입니다. 일반 텍스트의 최소 대비는 4.5:1, 큰 텍스트는 3:1입니다.

```js
function channel(value) {
  const srgb = value / 255
  return srgb <= 0.04045
    ? srgb / 12.92
    : ((srgb + 0.055) / 1.055) ** 2.4
}

function relativeLuminance([red, green, blue]) {
  return 0.2126 * channel(red) + 0.7152 * channel(green) + 0.0722 * channel(blue)
}

function contrastRatio(a, b) {
  const first = relativeLuminance(a)
  const second = relativeLuminance(b)
  const lighter = Math.max(first, second)
  const darker = Math.min(first, second)
  return (lighter + 0.05) / (darker + 0.05)
}

const coral = [240, 128, 128]
const white = [255, 255, 255]
const black = [0, 0, 0]
```

#f08080의 상대 휘도는 0.3552였습니다. 흰 글자와의 대비는 2.59:1로 두 기준을 모두 못 통과했습니다. 흰 글자 기준으로 4.5:1을 만들려면 바탕의 상대 휘도가 0.1833 이하여야 해서, 같은 색을 검게 가깝게 줄여 #b15e5e를 얻었습니다. 이 색과 흰 글자의 대비는 4.53:1로 기준을 넘었지만, 위에서 본 것처럼 명도와 채도가 함께 바뀌었습니다. 같은 #f08080 위에 검은 글자를 올리면 대비는 8.10:1이었습니다.

## 바탕을 어둡게 하거나, 밝은 색을 막거나, 다시 고르게 하는 길은 버렸습니다

바탕 명도를 계산으로 내리는 길은 가장 단순했습니다. 흰 글자를 유지할 수 있고, 숫자만 보면 기준을 통과합니다. 다만 사용자가 고른 밝은 산호색이 훨씬 어둡고 탁한 붉은색으로 바뀝니다. 고른 색이 그 사람의 인상이라면, 대비를 위해 그 색을 바꾸는 일은 다른 색을 보여주는 일과 같습니다. 그래서 이 길을 버렸습니다.

너무 밝은 색을 고르지 못하게 막는 길도 보았습니다. 대비는 쉽게 맞출 수 있지만, 밝은 색 자체를 쓰지 못하게 됩니다. 고른 색을 다시 바꾸라고 묻는 길도, 이미 정한 인상을 흔들어 택하지 않았습니다.

대신 고른 색은 바탕에 그대로 두고, 큰 제목처럼 그 위에 얹히는 글자만 짙은 색으로 바꿨습니다. 본문은 흰 카드 위에 두어 바탕과 글자의 대비를 카드 안에서 맞추고, 강조는 색을 바꾸는 대신 밑칠처럼 따로 표시하는 쪽으로 나누었습니다.

## 계산값이 기준을 넘는지와, 고른 색이 그대로인지를 같이 봅니다

확인할 때는 공식과 같은 계산으로 상대 휘도와 대비를 다시 풉니다. 일반 텍스트 4.5:1과 큰 텍스트 3:1을 각각 통과하는지를 적습니다. 그리고 고른 색의 16진 값, 명도, 채도가 그대로인지를 같이 봅니다. 대비만 올라가고 색이 바뀌었다면, 그 조합은 통과가 아닙니다. 글자 색만 바꾼 조합에서는 바탕 색이 기준 값과 같아야 합니다.

고른 색을 지키면, 밝은 바탕 위에 흰 글자를 쓰는 조합은 포기하게 됩니다. 그 대신 그 사람이 고른 색이 화면에서 같은 색으로 남습니다. 대비는 글자 색과 카드, 강조 방식처럼 바꿔도 되는 쪽에서 얻기로 했습니다.

색을 고르는 일은 인상을 정하는 일이고, 대비는 그 인상을 읽을 수 있게 만드는 일입니다. 계산을 풀어 보니 바탕을 낮추는 길은 숫자를 맞추는 대신 색을 바꿨고, 글자를 짙게 하는 길은 고른 색을 유지한 채 기준을 넘었습니다. 같은 날 막아야 할 조합이 늘어날 때 제약부터 다시 묻는 이야기는 이 글에서 다루지 않습니다.

대비는 고른 색을 바꾸지 않고, 글자와 배치처럼 바꿔도 되는 쪽에서 맞추려고 합니다.
